    <h2 id="process-section-3-heading">
        3. Analogy and Mental Model
    </h2>

    <!-- BLOCK 3.1: INTRODUCTION TO THE ANALOGY -->

    <h3>3.1 Imagine a Busy Restaurant Kitchen</h3>

    <p>
        Imagine a busy restaurant where several customers
        place orders for food.
    </p>

    <p>
        Each order describes what a customer wants.
        The kitchen has recipes, chefs, cooking stations,
        ingredients, and equipment needed to prepare
        those orders.
    </p>

    <p>
        The kitchen manager organises the work.
        The manager keeps track of orders, coordinates
        the available resources, and helps decide
        which order should be handled next.
    </p>

    <p>
        A computer system works in a comparable way.
        When you start an application, the operating
        system creates and manages a process.
        It coordinates the resources needed for
        that process to execute.
    </p>

    <div class="concept-note">

        <h4>The Main Idea</h4>

        <p>
            Think of a process as a particular order
            being carried out in the kitchen.
            The operating system is like the kitchen
            manager coordinating the work.
        </p>

        <p>
            This is a learning analogy. A computer
            process is not literally a food order,
            and an operating system is not a person.
        </p>

    </div>

    <!-- BLOCK 3.4: HOW THE ANALOGY WORKS -->

    <h3>3.3 Follow One Order Through the Kitchen</h3>

    <p>
        Let's follow one customer's order and see how
        the same general ideas appear in a computer.
    </p>

    <ol>

        <li>
            <strong>A recipe exists.</strong>

            <p>
                A recipe contains instructions for
                preparing a dish. Similarly, a program
                contains instructions stored on a computer.
            </p>
        </li>

        <li>
            <strong>A customer places an order.</strong>

            <p>
                The restaurant receives a request to
                prepare a dish. Similarly, a user may
                request that an application run.
            </p>
        </li>

        <li>
            <strong>The kitchen begins preparing the order.</strong>

            <p>
                The order becomes work being carried out.
                Similarly, the operating system creates
                and manages a process when a program
                is started.
            </p>
        </li>

        <li>
            <strong>The kitchen manager coordinates the work.</strong>

            <p>
                The manager keeps track of orders and
                coordinates available resources.
                Similarly, the operating system manages
                processes and their resource access.
            </p>
        </li>

        <li>
            <strong>The order may need to wait.</strong>

            <p>
                A kitchen may have different reasons
                for an order to wait. A cooking station
                may be busy, or an ingredient may not
                have arrived.
            </p>

            <p>
                A computer process can also wait for
                different reasons. It may be ready
                but waiting for CPU time, or it may
                be waiting for an event such as an
                input/output operation.
            </p>
        </li>

        <li>
            <strong>The order is completed.</strong>

            <p>
                The finished dish leaves the kitchen.
                Similarly, a process terminates when
                its execution ends.
            </p>
        </li>

    </ol>


    <!-- BLOCK 3.5: CONNECTING THE ANALOGY TO REAL CONCEPTS -->

    <h3>3.4 The Real Operating-System Concepts</h3>

    <p>
        The restaurant analogy helps us understand
        the general idea. Now let's connect it to
        the actual computer concepts.
    </p>

    <ul>

        <li>
            <strong>Program:</strong>
            A stored set of instructions that describes
            what a computer should do.
        </li>

        <li>
            <strong>Process:</strong>
            An executing instance of a program that
            the operating system manages.
        </li>

        <li>
            <strong>Operating system:</strong>
            System software that manages processes
            and coordinates access to computer resources.
        </li>

        <li>
            <strong>CPU:</strong>
            The processor that executes instructions
            belonging to running threads.
        </li>

        <li>
            <strong>Memory:</strong>
            Holds the instructions, data and other
            information needed during execution.
        </li>

        <li>
            <strong>Process scheduling:</strong>
            The operating system's method of deciding
            which ready thread should receive CPU time.
        </li>

        <li>
            <strong>Ready:</strong>
            A process has work that can proceed.
            More precisely, its runnable thread
            is waiting for CPU time.
        </li>

        <li>
            <strong>Waiting / Blocked:</strong>
            A thread belonging to a process is waiting
            for an event or operation, such as input/output,
            to finish.
        </li>

        <li>
            <strong>Termination:</strong>
            The process has finished its execution
            and is being or has been cleaned up.
        </li>

    </ul>

    <div class="concept-note">

        <h4>Important: Ready and Waiting Are Different</h4>

        <p>
            Imagine two restaurant orders.
        </p>

        <p>
            <strong>Order A:</strong>
            All ingredients are available, but the
            cooking station is busy. The order is
            ready for preparation.
        </p>

        <p>
            <strong>Order B:</strong>
            The order cannot continue because a
            required ingredient has not arrived.
        </p>

        <p>
            In a computer:
        </p>

        <ul>
            <li>
                <strong>Ready:</strong>
                Waiting for CPU time.
            </li>
            <li>
                <strong>Waiting / Blocked:</strong>
                Waiting for an event or operation.
            </li>
        </ul>

        <p>
            These are two different reasons why
            a process may not currently be executing.
        </p>

    </div>


    <!-- BLOCK 3.6: CPU AND PROCESS CLARIFICATION -->

    <div class="concept-note">

        <h4>Important: The Process Is Not the CPU</h4>

        <p>
            In the restaurant analogy, the order represents
            the process. The chef and cooking station
            represent the ability to carry out the work.
        </p>

        <p>
            In a computer, a process is the managed
            environment containing one or more threads.
            The CPU executes instructions belonging
            to those threads.
        </p>

        <p>
            A process does not need to use the CPU
            continuously. It may receive CPU time,
            pause while another thread runs, or wait
            for an event such as a file operation.
        </p>

        <p>
            The detailed process states and scheduling
            mechanisms will be explained in later sections.
        </p>

    </div>


    <!-- BLOCK 3.7: IMPORTANT LIMITATION OF THE ANALOGY -->

    <div class="concept-note">

        <h4>Important: An Analogy Is Not the Actual Mechanism</h4>

        <p>
            A restaurant kitchen helps us imagine how
            work is organised, but a computer does not
            operate exactly like a restaurant.
        </p>

        <p>
            A chef is a person who performs physical work.
            A CPU is an electronic processor that executes
            machine instructions.
        </p>

        <p>
            The operating system uses scheduling algorithms,
            data structures, memory management and
            hardware mechanisms. It does not manage
            processes by behaving like a human manager.
        </p>

        <p>
            Use the analogy to understand the relationships,
            not to assume that every restaurant activity
            has an exact technical equivalent.
        </p>

    </div>


    <!-- BLOCK 3.8: SECOND MENTAL MODEL -->

    <h3>3.5 A Second Mental Model: Your Desk and a Bookmark</h3>

    <p>
        Imagine reading a book at your desk.
        You stop reading to answer the telephone.
    </p>

    <p>
        Before leaving, you place a bookmark on
        the page where you stopped.
    </p>

    <p>
        When you return, the bookmark helps you
        find your place and continue reading.
    </p>

    <p>
        A computer also needs to preserve important
        execution information when a thread stops
        using the CPU temporarily.
    </p>

    <p>
        During a context switch, the operating system
        saves the necessary execution context of
        the thread being switched out and restores
        the saved context of the thread being switched in.
    </p>

    <div class="concept-note">

        <h4>What Does the Bookmark Represent?</h4>

        <p>
            The bookmark represents the idea of remembering
            where execution should continue.
        </p>

        <p>
            In a computer, the saved execution context
            contains more than a simple position. It can
            include information such as the program counter
            and processor register values.
        </p>

        <p>
            The bookmark is only an analogy. It does not
            represent the complete technical state of
            a process or thread.
        </p>

    </div>

    <div class="concept-note">

        <h4>Does Every Context Switch Mean Switching Processes?</h4>

        <p>
            No. A context switch can occur between
            threads belonging to different processes.
            It can also occur between threads belonging
            to the same process.
        </p>

        <p>
            This is why it is important to understand
            that a process can contain one or more threads.
        </p>

    </div>


    <!-- BLOCK 3.9: PRESERVED SUPPLEMENTARY ANALOGIES -->

    <h3>3.6 Two More Ways to Think About a Process</h3>

    <h4>Musical Score and Live Performance</h4>

    <p>
        Think of a program as a <strong>musical score</strong>
        and a process as a <strong>live performance</strong>.
    </p>

    <ul>
        <li>
            <strong>Musical score:</strong>
            Program instructions written down.
        </li>
        <li>
            <strong>Musician performing it:</strong>
            Process as an active instance of execution.
        </li>
        <li>
            <strong>Current position in the music:</strong>
            A simple way to imagine execution progress.
        </li>
        <li>
            <strong>Instruments and equipment:</strong>
            Resources such as CPU time and memory.
        </li>
    </ul>

    <p>
        The same musical score can be performed many times.
        Similarly, the same program can have multiple
        processes running at the same time.
    </p>


    <h4>Factory Blueprint and Work Order</h4>

    <p>
        A program is like a factory blueprint.
        A process is a work order that is currently
        being carried out on the factory floor.
    </p>

    <ul>
        <li>The blueprint describes how something should be made.</li>
        <li>Each work order has its own progress and status.</li>
        <li>The factory manager coordinates the available resources.</li>
    </ul>

    <p>
        These are additional mental models. The restaurant
        kitchen remains our main analogy for understanding
        process management.
    </p>


    <!-- BLOCK 3.10: ANALOGY SUMMARY -->

    <div class="concept-note">

        <h4>Remember the Three Mental Models</h4>

        <p>
            <strong>Restaurant kitchen:</strong>
            Helps explain processes, execution,
            resource coordination, scheduling,
            waiting and completion.
        </p>

        <p>
            <strong>Book and bookmark:</strong>
            Helps explain why execution information
            must be saved and restored when a thread
            stops and later resumes.
        </p>

        <p>
            <strong>Musical score and factory work order:</strong>
            Provide additional ways to understand the
            difference between instructions and active work.
        </p>

    </div>
