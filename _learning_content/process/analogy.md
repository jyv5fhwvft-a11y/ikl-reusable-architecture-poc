    <h2 id="process-section-3-heading">
        3. Analogy and Mental Model
    </h2>

    <h3>Musical Score and Live Performance</h3>

    <p>
        Think of a program as a <strong>musical score</strong>
        and a process as a <strong>live performance</strong>.
    </p>

    <ul>
        <li><strong>Musical score</strong> → Program (the written instructions)</li>
        <li><strong>Musician performing it</strong> → Process (the active execution)</li>
        <li><strong>Current position in the music</strong> → Program counter / execution state</li>
        <li><strong>Instruments and equipment</strong> → Resources (CPU, memory, files)</li>
    </ul>

    <p>
        The same musical score can be performed many times.
        Similarly, the same program can have multiple processes
        running at the same time.
    </p>

    <h3>Another Useful Picture: A Factory Work Order</h3>

    <p>
        A program is like a factory blueprint.
        A process is a work order that is currently being carried out
        on the factory floor.
    </p>

    <ul>
        <li>The blueprint stays the same.</li>
        <li>Each work order has its own progress, materials, and status.</li>
        <li>The factory manager (operating system) decides which work orders
            get machine time and when.</li>
    </ul>

    <h3>Mental Model to Keep</h3>

    <div class="concept-note">
        <p>
            <strong>Program = instructions stored on disk.</strong><br>
            <strong>Process = those instructions being managed while they run.</strong>
        </p>
    </div>
